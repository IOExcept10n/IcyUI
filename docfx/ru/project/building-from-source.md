# Сборка из исходников

Для участников разработки. Получите исходники с [GitHub](https://github.com/IOExcept10n/IcyUI) и работайте в ветке
`platform-independent` — основной долгоживущей ветке разработки.

## Требования

- .NET 10 SDK. Корневой `global.json` закрепляет его версию (10.0.x).
- Windows для сборки примеров на Stride и WindowsDX. CI собирает и тестирует на Windows, x64 и ARM64.

## Сборка и тесты

```
dotnet build "sources/IcyUI.sln"
dotnet test "sources/IcyUI.Tests/IcyUI.Tests.csproj"
```

`dotnet test` может вывести «Passed!», даже если тестовый хост упал, поэтому проверяйте и число `Total`. В названии папки
`MonoGame Sample` есть пробел: берите путь в кавычки. Пример работает на WindowsDX; для DesktopGL добавьте
`-p:MonoGameBackend=DesktopGL`.

## Соглашения

- Четыре выпускаемые библиотеки (`IcyUI`, `IcyUI.Design`, `IcyUI.MonoGame`, `IcyUI.Stride`) собираются **без
  предупреждений**. StyleCop включён, а Release считает предупреждения ошибками.
- У каждого публичного API полная XML-документация: справочник по API генерируется из неё.
- Ядро никогда не ссылается на движок; код движка остаётся в своём проекте `IcyUI.<Engine>`, а изменение ядра в
  отрисовке, вводе или публичном API проверяется на обеих интеграциях.
- Версии пакетов хранятся в одном месте, `sources/Directory.Packages.props`.

## Сборка этой документации

```
bash .github/scripts/build-docs.sh
dotnet docfx serve docfx/_site
```

Просматривайте по HTTP: у страницы, открытой с диска, нет панели навигации и поиска. Сборка строгая: любое
предупреждение DocFX её роняет. Каждая страница есть на английском (`docfx/en`) и русском (`docfx/ru`); для ещё не
переведённой страницы создаётся русская заглушка. Примеры кода берутся из компилируемых проектов с фрагментами и
протестированных файлов разметки, поэтому не могут разойтись с библиотекой.

## Pull request'ы

Для всего, что больше исправления, сначала заведите issue, чтобы обсудить дизайн. Изменение сопровождается тестами, а
поведение, видимое пользователям, — документацией на обоих языках.
