# Горячая перезагрузка и редактор в игре

В этом руководстве настраивается цикл правки интерфейса игры: меняйте разметку страницы в текстовом редакторе или в
редакторе поверх запущенной игры и смотрите результат без перезапуска. Используется пакет `IcyUI.Design` — инструмент
разработки; в выпущенной игре его нет.

Вам понадобится игра, загружающая страницу из разметки ([Первый экран](../getting-started/first-screen.md)). Страница
[Редактирование разметки и инструменты дизайна](../concepts/design-tools.md) описывает, что это за инструменты; здесь они
подключаются и показано, как с ними работать.

## 1. Подключайте пакет только в Debug-сборках

Добавьте пакет и сделайте ссылку условной, чтобы релизная сборка его не несла:

```xml
<ItemGroup Condition="'$(Configuration)' == 'Debug'">
  <PackageReference Include="IcyUI.Design" Version="0.1.0-alpha.1" />
</ItemGroup>
<!-- The code that uses it lives in a DevTools folder, compiled in Debug only. -->
<ItemGroup Condition="'$(Configuration)' != 'Debug'">
  <Compile Remove="DevTools\**" />
</ItemGroup>
```

Страницы загружаются из вывода сборки (`bin/Debug/.../Menu.xml`) — копии файла из вашего проекта. Правки в копии пропали
бы при следующей сборке, поэтому инструментам нужно знать, где лежат файлы вашего проекта.

- **Подключайте до загрузки первой страницы.** Сеанс отслеживает только страницы, загруженные после подключения.

## 3. Правьте в текстовом редакторе

При запущенной игре сохраните файл `.xml` в проекте. Через доли секунды живая страница меняется: `Width` кнопки, текст,
цвет, добавленный элемент. За кадром инструменты читают файл и применяют его к странице как одну правку.

- Это работает и для редакторов, которые сохраняют, записывая временный файл и переименовывая его.
- Несколько быстрых сохранений подряд применяются один раз.
- Файл, текст которого совпадает с тем, что уже есть в игре, игнорируется. Поэтому сохранение из редактора в игре
  (шаг 4) не перезагружает само себя.

Не всякая правка может изменить живую страницу. Правка внутри `Style`, `ControlTemplate` или элемента-свойства
(`<Button.Content>`) меняет документ, но не уже показанные элементы; документ сообщает `NeedsReload`. Загрузите страницу
заново, чтобы увидеть её. `ReloadablePage` делает это по **F5** из последнего текста документа:

## 4. Правьте в игре

Нажмите **F4**, чтобы показать редактор поверх запущенной игры. Щёлкните элемент, чтобы выбрать его, меняйте свойства на
панели справа, перетаскивайте его или добавляйте элементы из набора инструментов. **Ctrl+Shift+E** переключает режим
правки (щелчок выбирает) и режим взаимодействия (интерфейс работает как в игре, так что можно открыть меню и править
показанное в нём). **Ctrl+Z** и **Ctrl+Y** отменяют и возвращают.

**Save** на панели команд записывает текст документа в файл вашего проекта с сохранением форматирования и комментариев.
Слежение за файлами видит запись, обнаруживает, что текст уже совпадает с документом, и ничего не делает.

## Что вы построили

Запущенная игра, страницы которой следуют за вашим текстовым редактором, редактор поверх неё и F5 для правок, которые не
могут изменить живую страницу, — и всё это только в Debug-сборках. В релизе от этого ничего нет.

> [!NOTE]
> Править можно только страницы, загруженные из разметки после подключения сеанса. Элемент, созданный в коде, выбрать
> нельзя, а правка стиля или шаблона требует перезагрузки по F5. `NeedsReload` остаётся установленным, если правка его
> требовала, поэтому нажимайте F5 всякий раз, когда живая страница выглядит устаревшей.
