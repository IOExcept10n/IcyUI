# Написание интеграции с движком

IcyUI рисует и читает ввод через несколько интерфейсов, и интеграция с движком их реализует. Это руководство перечисляет,
что она предоставляет, в порядке построения, на примере FNA. В FNA есть API XNA, поэтому каркас похож на интеграцию с
MonoGame, которая служит полным образцом:
[`IcyUI.MonoGame` на GitHub](https://github.com/IOExcept10n/IcyUI/tree/main/sources/IcyUI.MonoGame).

> [!NOTE]
> `IcyUI.FNA` сегодня — заготовка; пакета для FNA пока нет. Руководство описывает, как строится интеграция, а не готовую
> интеграцию. Особенности FNA, например его нативные библиотеки, здесь не рассматриваются.

Вам понадобится хорошее знание целевого движка и страницы [Canvas, хост и дерево элементов](../concepts/canvas-and-host.md).
Игре ничего из этого не нужно: она лишь использует существующую интеграцию.

## Что предоставляет интеграция

| Часть | Интерфейс | Что делает |
|---|---|---|
| Рисование | `IRenderContext` | Рисует текстурированные прямоугольники внутри sprite batch, создаёт текстуры, сообщает область просмотра и масштаб дисплея. |
| Ввод | `IInputSystem` | Превращает состояние клавиатуры, мыши, геймпада и касаний в события IcyUI; ввод текста и буфер обмена. |
| Ресурсы | `IAssetContextFactory`, `IPlatformAssetImporter<T>` | Открывает контент движка и превращает потоки изображений в текстуры. |
| Хост | `IIcyHost` | Игровой компонент, который связывает три предыдущих с игровым циклом и владеет Canvas. |
| Точка входа | `UseIcyUI(this Game, ...)` | Строит конфигурацию и добавляет хост. |

Ядро IcyUI никогда не ссылается на движок; всё перечисленное — единственный код, который это делает.

## 1. Контекст отрисовки

`IRenderContext` рисует только текстурированные прямоугольники: Canvas вызывает `Begin`, затем `Draw` для каждого
прямоугольника, глифа и изображения, затем `End`. Сплошной цвет — это закрашенный `WhiteTexture`.

[!code-csharp[](../../../sources/IcyUI.Docs.Snippets.MonoGame/Guides/EngineIntegration.cs#render-context-outline)]

Места, где раньше ошибались, — посмотрите их в версии для MonoGame:

- **Прямая альфа.** Текстуры IcyUI не premultiplied, поэтому sprite batch должен смешивать с прямой альфой; смешивание
  premultiplied по умолчанию делает края сглаженного текста слишком яркими.
- **Тест ножниц.** Обрезка использует прямоугольник ножниц, и состояние растеризатора должно включать тест ножниц, иначе
  любая обрезка молча игнорируется.
- **`Flush`** вне `Begin`/`End` ничего не делает; он завершает и перезапускает batch при смене ножниц или эффекта.
- **Масштаб дисплея.** Сообщайте масштаб DPI монитора (`DisplayScale`, `DisplayScaleChanged`), опрашивая его на каждом
  обновлении, чтобы работало [масштабирование](../concepts/scaling.md). Платформенных поставщиков даёт ядро.

Каждое устройство реализует свой интерфейс: читает состояние движка в `Update` и вызывает события IcyUI (нажатие,
отпускание, перемещение, навигация). Текстовый ввод приходит из окна движка (события символов, IME), а не из нажатий
клавиш. Если движок не умеет сообщать об устройстве, оставьте его `null`: Canvas справится. Буфер обмена — единственная
часть, зависящая от ОС: выбирайте его селектором буфера обмена из ядра, а не пишите по одному на каждый движок.

## 3. Ресурсы

Контекст ресурсов открывает контент по URI (конвейер контента движка, файлы, встроенные ресурсы), а импортёр превращает
поток изображения в текстуру движка. Зарегистрируйте оба в конфигурации ресурсов; в `IcyUI.MonoGame` есть
`MonoGameAssetContextFactory` и `TextureImporter` по несколько строк каждый.

## Что вы построили

Пять частей, нужных движку, в порядке, позволяющем проверять каждую: нарисовать прямоугольник, прочитать щелчок,
загрузить текстуру, а затем запустить страницу разметки через хост.
